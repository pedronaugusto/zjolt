# Exhaustive classification of every name `tools/coverage.sh Physics/Body`
# and `tools/coverage.sh Physics/Collision` report unbound, against the four
# categories:
#
#   INTERNAL         solver step, island building, *Internal, SIMD, tree/
#                     allocator internals. No host ever calls it.
#   EXTENSION_POINT   a C++ interface a host would subclass, already turned
#                     into a C callback. The zjolt entry point is named.
#   BOUND_ELSEWHERE   reachable under a different name, or trivially
#                     composable/reconstructable from what is already bound,
#                     or is a *Settings companion class (settings do not
#                     cross this ABI by design; the zjoltXCreate* call that
#                     takes the same parameters directly is named).
#   REAL_GAP          bind-worthy. "(bound)" marks ones bound in this pass;
#                     "(deferred: reason)" marks ones judged real but not
#                     bound, with why.
#
# Same tooling caveat throughout: the coverage script's own bound-name
# extraction regex `[A-Za-z_ *]*` cannot match a return type containing a
# digit (uint32_t, uint64_t, int32_t, ...), so a genuinely-bound entry point
# with such a return type is invisible to it and its Jolt counterpart shows
# as spuriously unbound. Caught twice below (GetNum*StepsOverride,
# Get/SetInverseMass — the latter additionally hidden because Jolt's own
# one-line inline definition puts JPH_ASSERT on the same line the method-name
# regex scans, which the parser's own JPH_ASSERT-skip rule then drops
# entirely, so it never even reaches the "unbound" list to be second-guessed).
# Neither is a reason to trust a "bound" verdict from the tool without
# checking; both are reasons a "looks bound" reading from raw grep can also
# be wrong in the other direction.
#
# UPDATE, after tools/coverage.sh was fixed mid-pass (commit "Match coverage
# by words, not by the flattened name"): re-ran both areas against the fixed
# matcher and diffed old-vs-new unbound sets. The new set is a strict subset
# of the old one in both areas (nothing newly appeared as unbound that this
# file had not already classified), so nothing below was missed. Of the names
# that flipped to "bound", every one already bound in this session (see the
# REAL_GAP "(bound)" entries) is a genuine new match, confirmed by diffing
# ffi/zjolt_body.h and ffi/zjolt_constraint.h against their committed
# versions before this session's edits.
#
# The fix is not perfect: when a name's only words of 4+ characters happen to
# be a single word (Get/Set/Add/Is are all under four characters and get
# dropped), matching degrades back to a bare substring test, and a few names
# flip to "bound" on a coincidental match against an UNRELATED SoftBody
# entry point that happens to share that one word — GetRadius and
# GetTopRadius match only via "radius" against zjoltSoftBodyGetVertexRadius,
# GetNumFaces matches only via "faces" against
# zjoltSoftBodySharedSettingsAddFaces/zjoltSoftBodySetFacesDoubleSided, and
# GetVertices matches only via "vertices" against
# zjoltSoftBodySharedSettingsAddVertices — none of which is a shape-radius or
# shape-vertex binding. Checked directly (`grep radius`/`faces`/`vertices`
# over the bound-name list): no shape-introspection entry point exists.
# Their REAL_GAP verdicts below stand; the raw tool output for these four
# specifically should not be trusted without this check. Same class of
# false positive on the Body side for TryGetBody (survives only as "body",
# matching any zjoltBody* name) and LockAngular (survives as "lock" +
# "angular", matching zjoltBodyGetAngularVelocityLocked purely because
# "locked" contains "lock") — both already correctly INTERNAL below, for
# reasons independent of whichever way the tool's substring check falls.
